# Обережно 🤍

Telegram-бот с бережными посланиями. Отправляет подписчицам одно послание утром,
днём и вечером по московскому времени.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить своими значениями
npm start
```

Важно: бот работает в режиме polling, а Telegram разрешает только одно
подключение на токен. Если бот запущен на Render, локальный запуск отберёт у него
сообщения — в логах будет ошибка 409.

## Структура

| Файл | За что отвечает |
|---|---|
| `bot.js` | Команды, расписание, HTTP-заглушка для Render |
| `src/db.js` | Подписчицы в Supabase: добавить, удалить, посчитать |
| `src/content.js` | Колода посланий: каждое по разу, потом новый круг |
| `src/questions.js` | Утренние вопросы и отклики на ответы |
| `src/mood.js` | Ответ подписчицы на утренний вопрос (до конца дня) |
| `src/sender.js` | Доставка: лимиты Telegram, повторы, чистка отписавшихся |
| `messages.json` | Тексты посланий по времени суток |
| `responses.json` | Вопросы, кнопки и отклики |
| `images/` | Картинки к посланиям |

## Послания

Добавляются в `messages.json` в нужную секцию (`morning`, `day`, `evening`):

```json
{ "text": "Текст послания", "image": "images/morning/morning1.png" }
```

Поле `image` можно поставить `null` — тогда уйдёт просто текст. Путь указывается
от корня проекта.

Послания выдаются колодой: порядок случайный, но каждое послание приходит по
одному разу, пока не кончится вся пачка — повтор через день невозможен. Колода
живёт в памяти процесса и перемешивается заново после перезапуска бота.

## Вопросы

Утреннее послание заканчивается вопросом — про чувства, внимание, энергию, тело.
Вопросы лежат в `responses.json` и идут по кругу: каждое утро следующий.
Форматов два, и они чередуются.

**С вариантами ответа.** У вопроса есть `options` — приходит с кнопками. У
каждого варианта три текста:

- `label` — надпись на кнопке;
- `ack` — что бот отвечает сразу после нажатия;
- `evening` — строка, с которой начнётся её вечернее послание в этот день.

**Открытый.** У вопроса нет `options` — приходит без кнопок, с приглашением из
`openInvite`. На такой вопрос отвечают своими словами или молча, себе. Строка для
вечера берётся из поля `evening` самого вопроса.

Ответить словами можно на любой вопрос, даже если у него есть кнопки. Если она и
нажала, и написала — вечером учтётся нажатие, оно точнее.

Ответ хранится в памяти процесса до конца дня. Если бот перезапустится между
утром и вечером, вечернее послание просто уйдёт обычным, без отклика. Чтобы
ответы переживали перезапуск, нужны колонки в Supabase — это следующий шаг.

Если подписчица отвечает своими словами, а не кнопкой, бот откликается фразой из
`freeText`. Текст её сообщения нигде не сохраняется и не пишется в логи.

## Команды

`/start` — подписаться, `/stop` — отписаться, `/morning`, `/day`, `/evening` —
послание прямо сейчас, `/help` — справка. Служебные: `/test` (бот жив),
`/count` (сколько подписчиц).

## База

Таблица `subscribers`, колонка `chat_id`. Отписавшиеся и заблокировавшие бота
удаляются автоматически при рассылке.

**Стоит добавить:** UNIQUE-констрейнт на `chat_id` в дашборде Supabase — это
защитит от дублей, если две команды `/start` придут одновременно.

## Деплой

Render, тип сервиса Web Service (нужен открытый порт — его держит HTTP-заглушка
в `bot.js`). Переменные окружения задаются в настройках сервиса, файл `.env` в
репозиторий не попадает.
